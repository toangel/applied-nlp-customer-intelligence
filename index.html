Where is Customer Service effort actually going — and which customer issues should we fix first?

02 — Solution

A layered NLP architecture: LLMs for discovery, transformers for reliable classification, embeddings for issue discovery.

Instead of asking one model to do everything, the solution separated the problem into stages, using the model family best suited to each task.

01
Source preparation

Clean the conversations

Each channel has a different structure, so preprocessing focused on keeping the earliest customer-authored content and removing conversational noise.

Email
Use the first customer email in each case.
Remove greetings, signatures, reply headers and quoted history.
Live chat
Keep the first 10 customer messages.
Remove agent turns, system messages, greetings and repetitive acknowledgements.
Call transcripts
Keep early customer-authored speech.
Remove agent dialogue, fillers, repeated speech and transcription artefacts.
Design principle: channel-specific preprocessing → consistent semantic representation → shared NLP taxonomy.
02
Intent extraction

Extract the customer’s core reason for contact

At million-record scale, using a large LLM to summarise every interaction would add significant inference cost and latency. Instead, lightweight summarisation / intent-extraction models were used to reduce longer customer conversations to the primary reason for contact before downstream classification and semantic similarity.

BART-large-CNN
Lightweight summarisation compresses long conversations, while retaining enough context to represent the customer’s request.
FLAN-T5-base
Instruction-based extraction focuses more directly on the requested action, e.g. “Customer requests removal of a previously submitted review.”

LLM-assisted taxonomy discovery

Discover recurring themes and cross-check candidate labels

A sampled set of customer intents was passed through GPT-4o using structured prompts to propose concise issue labels and candidate themes. Claude Sonnet independently classified the same intents, providing a cross-model check before human review and consolidation into a stable, business-readable taxonomy.

04
Supervised classification

RoBERTa-large classifies the extracted customer intent at scale

The canonical customer intent was passed to a fine-tuned RoBERTa-large classifier and assigned to one of 15 predefined contact-reason themes. Using the normalised intent representation reduced conversational noise and provided a more standardised input than the full email, chat or transcript.

Model: RoBERTa-large
Taxonomy: 15 stable high-level themes
05
Structured output

Broad themes become measurable customer signals

Messages were transformed into consistent model-derived contact reasons such as refund, booking amendment, pickup confirmation, cancellation, help contacting customer/supplier, ticket and payment. This created a more dependable operational demand view than manually selected Salesforce fields.

06
Embeddings & sentence similarity

Group semantically similar intents inside each theme

High-level classification answered “what broad topic is this?” The cleaned or normalised customer intent was then converted into a sentence embedding. Cosine similarity compared semantic proximity, allowing differently worded requests with the same meaning to be grouped within each predicted theme.

04 — Key decisions

Why the solution was designed this way

The architecture balanced discovery quality, inference cost, taxonomy stability and the need to surface new customer issues over time.

Decision 1

Use LLMs selectively

GPT-4o and Claude Sonnet supported taxonomy discovery and validation. RoBERTa handled high-volume classification, avoiding the cost and latency of LLM inference across 1.48M interactions.

Decision 2

Separate themes from issues

15 stable themes provided a consistent reporting layer, while semantic similarity uncovered 108 more granular issues that Product and Operations could act on.

Decision 3

Preprocess by channel

Email, chat and call transcripts contain different types of noise. Channel-specific cleaning preserved the customer’s original intent before applying a common NLP framework.

Why this architecture scales

Generative models are used where reasoning adds the most value: discovering and validating the taxonomy. High-volume inference is then handled by RoBERTa and semantic similarity, making the pipeline more cost-efficient and repeatable.

What changes over time

The 15-theme taxonomy stays stable enough for consistent trend reporting, while similarity-based clustering can surface new granular issues as customer behaviour changes.

03 — Granular issue discovery

From a broad theme to a specific problem to fix

Within each high-level theme, semantic grouping surfaced recurring customer problems that would otherwise be hidden inside the overall contact volume.

Same intent, different wording

Review-removal requests looked very different in raw text but represented the same underlying customer need.

One theme, multiple problems

Within “Update itinerary”, similarity grouping separated duration mismatches, start-time changes and additional-departure requests — each pointing to a different potential fix.

05 — Model accuracy guardrails

Accuracy was treated as an ongoing quality-control system, not a single model score.

Because customer intent can be ambiguous and the taxonomy evolves, model quality was assessed at multiple levels: classification performance, human agreement, semantic-cluster coherence and production monitoring. Each layer answers a different failure mode.

01 · Ground truth

Human-labelled validation set

Maintain a stratified sample across all 15 themes and compare model predictions with manually reviewed labels. Refresh the sample as contact patterns and taxonomy definitions evolve.

02 · Class-level quality

Precision & recall by theme

Evaluate each theme independently rather than relying on one aggregate metric. This prevents strong high-volume classes from hiding weak performance on smaller or easily confused themes.

03 · Error diagnosis

Confusion & disagreement analysis

Review the theme pairs the model confuses most often. Use those errors to improve taxonomy definitions, training examples and decision boundaries rather than simply retraining blindly.

04 · Human baseline

Inter-annotator agreement

Have independent reviewers label the same sample and measure agreement. This establishes how objectively the themes can be distinguished and provides a realistic benchmark for model performance.

05 · LLM discovery

Independent model verification

Candidate LLM classifications are cross-checked by a second model. Agreement increases confidence; disagreements and ambiguous cases are routed for human review before they influence the taxonomy.

06 · 108 issues

Semantic-cluster quality review

For sentence-similarity grouping, manually sample messages within each cluster to assess semantic coherence and actionability. The question is not only “are these similar?” but “do they represent the same underlying issue that a team could act on?”

Production guardrail

Monitor theme distribution, confidence and disagreement patterns over time. Sudden shifts can indicate emerging customer issues, taxonomy drift or model degradation. Low-confidence and novel cases feed back into human review, creating a continuous monitor → review → refine → revalidate loop.
